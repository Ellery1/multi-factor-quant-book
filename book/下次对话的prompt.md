## 任务

改写 `book/part2-理论篇/` 下的 ch03、ch04、ch05、ch06 四章的数学推导部分，使其对非数学专业读者更友好。

## 背景

这是一本面向A股散户的多因子量化投资教材。读者有炒股经验但数学能力有限（虽然读过本科数学但已经还给老师了）。当前的理论篇写法是"先推导后解释"——读者看到公式时还不知道"这段推导要解决什么投资问题"，导致迷失。

## 改写原则

在每个核心数学推导段**之前**，插入一个通俗的"业务导读框"，格式如下：

```markdown
> 📌 **本节要解决的问题**：[用一句话说清楚投资问题，如"EP高的股票未来收益到底比EP低的高多少？"]
>
> **我们的做法**：[一句话说方法，如"对300只股票画散点图，拟合直线看斜率"]
>
> **得到的结论**：[一句话说结果，如"斜率β就是答案——EP每高0.01，月收益平均多0.5%"]
>
> 以下是这个结论的数学推导过程。如果你只想知道结论可以跳到下一节。
```

## 技术注意事项

1. **分批处理**：一次只改一章。改完一章后立刻保存（用 fsAppend 分段写入），确认成功后再改下一章。不要试图一次性写入超大文件。

2. **写入方式**：由于文件较大（每章400-600行），采用以下策略：
   - 先用 `readFile` 读取当前文件内容
   - 找到需要插入"业务导读框"的位置（根据上面列出的小节标题定位）
   - 用 `strReplace` 在对应段落**之前**插入导读框
   - 不修改原有推导内容，只在前面"加帽子"

3. **不要重写全文**：保留所有现有数学推导不变，只是在关键推导段前面加入通俗概述。这样工作量可控且不会引入新错误。

4. **顺序**：按 ch03 → ch04 → ch05 → ch06 的顺序逐章处理。每章处理完后做一次 git commit。

5. **导读框风格要求**：
   - 语言必须通俗——假设读者是完全不懂数学的散户
   - 用投资场景而非抽象概念来描述问题
   - "结论"部分要直接给出可操作的投资含义
   - 最后一句"如果你只想知道结论可以跳到下一节"是固定的——给读者跳过数学的选项

## 完成标准

- 理论篇四章中每个核心推导段都有"业务导读框"（共约20个框）
- 所有原有内容（推导、公式、代码、worked examples）保持不变
- 每章改完后 git commit 一次
- 全部完成后 `git push origin master`
